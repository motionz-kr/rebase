# AWS SSM connections and local MCP

Issue: https://github.com/motionz-kr/rebase/issues/207

## Scope

Add direct/SSM connection routing for MySQL and PostgreSQL. Store only AWS profile name,
region and managed EC2 instance ID alongside the existing destination host/port.
Use installed AWS CLI and Session Manager plugin; retain existing DB Keychain secrets.
IAM DB authentication and advanced certificate profiles remain separate features.

## Design

- Domain validates connection mode and SSM settings (TDD).
- A tunnel port resolves the destination into a loopback endpoint. The application
  connection service orchestrates resolution; SQL adapters use that resolver before
  opening connections. UI, introspection, queries, cancellation and MCP share it.
- SSM adapter launches argv directly (no shell), selects an available loopback port,
  waits for plugin readiness, coalesces concurrent requests, reuses live tunnels,
  replaces exited tunnels on the next operation and cleans up process trees.
- Each engine owns its tunnels; desktop and separate MCP engines choose independent
  ports. Never replay a failed statement or silently fall back to direct access.
- SQLite migration stores routing metadata with backward-compatible direct defaults.
- Connection UI exposes routing fields and actionable errors through connection test.

## Steps

1. Write failing domain, resolver, command/lifecycle and persistence tests.
2. Implement port, SSM adapter, application wiring and both SQL adapters.
3. Persist routing metadata and add UI fields with form tests.
4. Build and run Electron Playwright tests against an isolated fake AWS executable
   forwarding to a local DB. Verify MCP stdio queries in an independent engine.
5. Run affected/full Go tests and renderer/desktop checks; update architecture,
   security, MCP and usage docs. Preserve actual user and production data.

No commit, push or merge unless separately requested. AWS live verification requires
an authorized AWS test environment; automated local verification must never use production.

## Custom document extension

The user's existing command selects `Revisit-RdsPortForwarding` and passes only
`localPortNumber`. Extend the same feature branch with optional `documentName`
and `destinationMode` (`remote-host` default, `document` for a document-owned DB
destination). In document mode, omit host/portNumber from CLI parameters and hide
unused DB host/port fields; database/user/password remain normal DB settings.
Keep local ports engine-owned so desktop and standalone MCP can run concurrently.

Validate names against the AWS StartSession document-name pattern, reject option
prefixes and unknown modes, and require a document name in document mode. Include
the document/mode in tunnel identity and preserve them in existing JSON storage
without a new schema migration. Use TDD for validation, argv and renderer mapping;
extend the real Electron/MCP E2E fake document to reject any extra host/portNumber
parameters. Verify save/edit, queries, restart, mode changes and independent MCP.
Actual AWS document contents and connectivity remain a deployment check.
