# 다중 쿼리 정책 승인 후 중단 지점 재개

## 문제

`CREATE TABLE`, `ALTER`, `UPDATE`처럼 여러 문장을 순차 실행할 때 중간 문장에서 엔진 정책 승인이 발생하면, 현재 실행 루프가 종료된 뒤 정책 배너가 편집기 전체 SQL을 다시 실행한다. 이미 성공한 앞쪽 문장이 재실행되어 "이미 존재함" 오류가 나고 사용자가 앞부분을 직접 삭제해야 한다.

## 목표

- 정책 승인 후 이미 성공한 문장을 건너뛰고 차단된 문장부터 재개한다.
- 재개 시 원래 문장 순서, 결과 집합, 블록별 상태를 유지한다.
- 사용자가 SQL을 수정하거나 새 실행을 시작하면 이전 재개 지점을 폐기한다.
- 권한 승인 흐름과 destructive 정책 승인 흐름 모두 같은 재개 동작을 사용한다.

## 구현 순서

1. 재개 상태를 순수하게 계산하는 renderer helper와 실패 테스트를 먼저 추가한다.
2. `QueryEditor`에 탭별 pending multi-run continuation을 연결한다.
3. 정책 배너 승인 버튼이 전체 실행이 아닌 저장된 statement index부터 재개하도록 수정한다.
4. SQL 변경·새 실행·취소·성공/실패 종료 시 stale continuation을 정리한다.
5. renderer unit test와 기존 desktop E2E를 실행한다.
6. 일회용 SQLite DB로 실제 Electron에서 앞 문장 성공 → 중간 정책 승인 → 재개 → 뒤 문장 성공 흐름을 Playwright로 검증한다.

## 검증 기준

- 앞 문장은 정확히 한 번만 실행된다.
- 정책으로 중단된 문장은 승인 후 한 번 실행된다.
- 뒤 문장은 중단 시점부터 순서대로 실행된다.
- 결과 탭과 블록 상태가 성공/실패/미실행을 올바르게 표시한다.
- SQL을 수정한 뒤 실행하면 이전 continuation을 재사용하지 않는다.
