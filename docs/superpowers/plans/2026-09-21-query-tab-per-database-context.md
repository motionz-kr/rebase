# 데이터베이스별 쿼리탭 및 외부 요청 포커스

## 문제

스키마 탐색기에서 다른 데이터베이스의 `쿼리 입력` 또는 `500개 조회`를 누르면 현재 포커스된 연결/쿼리탭에 요청이 전달되지 않거나, 기존 쿼리탭의 데이터베이스 컨텍스트를 덮어쓴다. 그 결과 기존 세션을 유지한 채 다른 데이터베이스 작업을 열 수 없다.

## 목표

- 스키마 탐색기에서 SQL 요청을 열 때 대상 연결을 먼저 포커스한다.
- `쿼리 입력`과 `500개 조회`는 대상 데이터베이스에 고정된 새 쿼리탭을 연다.
- 기존 A 데이터베이스 탭과 수동 세션은 그대로 유지한다.
- 자동 실행 요청은 새 탭이 활성화된 뒤 그 탭의 데이터베이스/세션으로 실행한다.
- 다른 연결 프로필에서 온 요청도 동일하게 올바른 연결 패널로 이동한다.

## 구현 순서

1. SQL query request에 새 탭 요청 의도를 추가하고 순수 request 테스트를 보강한다.
2. `QueryEditor`가 외부 요청 시 대상 데이터베이스의 새 탭을 만들고, 활성화 완료 후 실행하도록 연결한다.
3. `App`의 스키마 탐색기 요청에서 대상 연결을 포커스하도록 수정한다.
4. 기존 탭 세션 유지와 새 탭 자동 실행을 Playwright SQLite E2E로 검증한다.

## 검증 기준

- A 탭에서 Manual 세션을 연 뒤 B 데이터베이스의 쿼리 입력을 누르면 A 탭과 세션이 유지되고 B 탭이 추가된다.
- B 데이터베이스의 500개 조회 요청은 B 탭에서 실행되고 결과가 표시된다.
- 다른 연결 프로필에서 요청해도 해당 프로필 패널이 활성화된다.
