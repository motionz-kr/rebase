# 연결 자격 증명 복구 플랜

## 문제

0.29.0 이전 프로필 편집은 빈 `secretRef`를 저장해 Keychain 비밀번호와의 연결을 끊을 수 있었다. 0.29.0부터 이후 편집은 기존 참조를 보존하지만, 이미 참조가 비워진 프로필은 복구하지 않는다. 또한 `GetProfile`이 Keychain의 모든 읽기 오류를 빈 비밀번호로 바꿔 DB 인증 실패로 오진할 수 있다.

## 구현 순서

1. 과거 데이터처럼 비어 있는 참조를 가진 프로필에서 결정적 참조(`secret-<profile id>`)로 기존 비밀번호를 찾고, 성공하면 프로필 참조도 복구하는 실패 테스트를 추가한다.
2. 프로필 수정 시 기존 참조가 비어 있으면 결정적 참조를 사용해 새 비밀번호 저장과 참조 복구가 이루어지는 테스트를 추가한다.
3. Keychain의 실제 항목 없음과 접근 오류를 구분한다. 항목 없음은 비밀번호 없는 DB를 지원하도록 빈 비밀번호로 유지하고, 그 외 읽기 오류는 상위에 전달하는 테스트를 추가한다.
4. 포트/어댑터 및 application service를 최소 수정한다.
5. 임시 metadata DB와 SQLite 파일을 사용하는 Electron E2E에서 과거의 빈 참조를 재현하고 재연결 및 저장된 참조 복구를 확인한다. 테스트 프로필은 끝에 삭제해 임시 Keychain 항목도 제거한다.
6. Go 테스트, renderer/desktop 빌드, 격리된 Electron E2E로 검증한다.

## 안전성

- 실제 등록된 프로필, 사용자 metadata DB, 운영 DB는 열거나 수정하지 않는다.
- 비밀번호는 OS Keychain에 그대로 두고, 비밀값은 DB나 오류 메시지에 기록하지 않는다.
- DB 접속 테스트는 격리된 SQLite 파일에서 수행한다.
